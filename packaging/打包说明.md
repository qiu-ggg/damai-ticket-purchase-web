# 打包成 exe

给不想装 Python 的客户用。客户机器上仍然要有 Chrome，但不需要 Python。

## 一条命令

```
.build-venv/Scripts/python packaging/build.py
```

产物：

```
dist/大麦抢票/      ← 整个文件夹发出去（不能只拎 exe 出来）
```

★ 打包前，上一轮的产物会被**改名挪到** `dist/_old/<时间戳>/`，不是删掉。
原因见「踩过的坑 ⑦」。`dist/_old/` 里都是旧 exe，确认新版没问题后整目录删掉即可 ——
它不在交付范围内。

打完跑一遍自检：

```
.build-venv/Scripts/python packaging/verify.py          # 查产物本身，顺带真起 exe 跑两条命令
```

`verify.py` 会真起 exe 跑 `--runner --paths`（随包模块逐个 import）和 `--runner --env`
（环境检测），所以「产物在不在」和「业务能不能跑」一起验了。

## 验证过什么

`packaging/verify.py`：产物存在、exe 能跑、数据目录确实**可写且落在 exe 同级**、
**随包模块一个不漏**（逐个 import 一遍，见下）、带没带驱动、
包里没有用户数据（`accounts.json` / `credentials.json`）、
包里没有短信密钥和日志。

「随包模块」那一条单列出来，是因为它最容易漏：`damai_wizard` 的子进程角色
用 `--runner` 起，而 `account_runner` / `concert` / `config` 这些是**裸模块名**
（靠运行时改 `sys.path` 才 import 到），PyInstaller 的静态分析看不见，
必须在 spec 的 `HIDDEN` 里手工列。漏一个的症状是：程序能开、界面正常，
点到「全部启动」才 ImportError —— 客户只会说「点了没反应」。
现在 `大麦抢票.exe --runner --paths` 会把它们逐个 import 并报结果。

手工验证过、`verify.py` 覆盖不到的（`doc/多账号使用说明.md` §6.7 有完整清单）：

- **数据落点能持久**：配好账号 → 关掉 → 重新启动三次，配置和登录态都还在。这是 `_MEIPASS` 那个坑的照妖镜。
- **窗口行为对**：双击直接进「大麦抢票 · 配置」主界面，不会先弹别的窗口。
- **短信通知在 exe 里能跑**：`大麦抢票.exe --runner notify --check` / `--show` 都能出结果，
  且 `notify.json` / `notify_secret.txt` 落在 exe 同级（不是解压的临时目录）。

## 短信通知（旁路，默认关）

两个模块随包打进去：`notify.py`（发送）、`notify_settings.py`（配置）。
两个都列在 `damai_app.spec` 的 `HIDDEN` 和 `--runner --paths` 的自检清单里。


**不需要装阿里云 SDK。** 签名是自己按 POP v1.0（HMAC-SHA1 + `urllib`）实现的 ——
这东西要进 exe，多一个第三方依赖就多一个「客户机器上装不上 / 漏打进包」的机会，
而签名算法就那几行。

`build.py` 打完会把 `notify_secret.txt` / `notify_state.json` 清掉
（AccessKeySecret 的密文本机的，没理由递出去）；
`build.py` 打完会把 `notify_secret.txt` / `notify_state.json` 清掉
（AccessKeySecret 是本机的，没理由递出去）；
`notify.json` **不清** —— 里面没有密钥，而且是发布方配一次就固定下来的那份
（模板号、签名），客户不用自己再对一遍。`verify.py` 里有专门一条盯着
「包里没有 `notify_secret.txt`」。

试跑时留下的：`damai/config.json` 里写着观演人真名和演出链接，`logs/` 里写着
什么时候抢了哪场票。清单在 `build.py` 的 `RUNTIME_JUNK` / `RUNTIME_JUNK_DIRS`，
`verify.py` 逐条对着查。

配置与用法见 `doc/多账号使用说明.md` 第五节第 9 条。

## 踩过的坑

**① 验证脚本自己可能是恒真的。** 早先有一条「包里没有私钥」写的是
`check(..., True)` —— 恒真，等于没查。后来改成真去扫包里每个文件的内容，
而且先拿一份已知含私钥的样本自证扫描器是灵的。

同理，「某个功能能不能起来」这种检查，如果验的是「不依赖该功能的那条命令」，
就永远是绿的。挑验证用的命令时，得挑真会走到那段代码的那条。


**⑤ 打包版一开抢就「出错」（2026-10-08 修）。** 控制台编码：向导是用
`CREATE_NEW_CONSOLE` 起 runner 的，那扇新窗口继承中文 Windows 的 GBK 代码页；
源码形态下调用方还带着 `-X utf8` / `PYTHONUTF8=1`，**打包后这两样都没有了** ——
于是 `print("⏳ 正在检查 Chrome 环境...")` 当场 `UnicodeEncodeError`，
把整个账号打断，日志里只有一行 codec 报错，看起来像「点了一下就出错」。
修法是 `account_runner.main()` 开头的 `_setup_console_encoding()`：
自己把 stdout/stderr 钉成 UTF-8、把控制台代码页切到 65001，不看调用方脸色；
向导两处 `Popen` 也补上了和 `task_manager` 同一套环境变量。
（2026-10-09 起向导那两处改成 `CREATE_NO_WINDOW`、输出重定向进 `runs/` 日志，不再弹窗口；
但编码兜底照旧必要 —— 手动在 cmd 里跑 `--runner` 时输出仍然落在 GBK 控制台上。）

**⑥ selenium 只收了个类型存根（2026-10-08 修）。** `webdriver.ChromeOptions()`
是**懒加载**的：`selenium/webdriver/__init__.py` 的 `__getattr__` 到运行时才
import `selenium.webdriver.chrome.options`，PyInstaller 的静态分析看不见这条路。
打出来的包里 `_internal/selenium/webdriver/chrome/` 只有 `__init__.pyi`，
一点「开始抢票」就 `ModuleNotFoundError`。修法是 `damai_app.spec` 里加
`collect_submodules("selenium")`。钉法两条：`verify.py` 直接从 exe 的
**PYZ 归档**里查这个模块在不在；并真跑一遍 `大麦抢票.exe --runner --env`，
要求报告里「抢票组件」是 `[OK]` —— `env_check` 为此加了一项，客户自己点
「环境检测」也能提前看见，不用等到开抢才发现包是坏的。

**⑦ 打完包「整段失败」，其实只是旧目录删不动（2026-10-08 修）。**
PyInstaller 的 COLLECT 碰到同名输出目录会直接 `rmtree`。本机这个删除会被
安全删除拦截器挡下（一次 1000+ 个文件，超过 50 的阈值），日志里只有一行
`SAFE_DELETE_BULK_CONFIRM_REQUIRED`，结果是 `[失败] dist/大麦抢票` ——
看着像打包坏了，实际新 exe 一个都没生成。
修法是 `build.py` 里加 `park_existing_dist()`：开打之前先把旧产物**改名**
挪到 `dist/_old/<时间戳>/`（改名不是删除，不触发拦截），PyInstaller 面对的
就是空目录了。顺带还解决了另一半问题 —— 旧目录留在原地的话，
`clean_runtime_junk()` 会把它连同 exe 旁边那份本机配置一起清掉。

**⑧ 旧产物目录改名也失败时，用 `--dist` 换地方出包（2026-10-08 补）。**
⑦ 的前提是「旧目录改得动名」。还有一种情况改不动：目录被**当成某个进程的
工作目录**，或者被杀软 / 索引器 / 预览服务持着句柄。这时候 `park_existing_dist()`
只会在日志里留一句「挪不动」，接着 PyInstaller 依然要 rmtree 那个目录 ——
而连父目录 `dist/` 都改不了名（Windows：子树里有东西被占，祖先也动不了），
于是整包还是出不来。

判断方法：目录里每个文件、每个子目录都能单独改名，**唯独目录本身改名报
`winerror=5 拒绝访问`**，就是这一种。

出包办法是 `--dist` 换一个干净目录：

```
.build-venv/Scripts/python packaging/build.py --dist D:/_newdist
```

打完把 `_newdist/大麦抢票/` 里的**内容**（不是目录本身）搬回
`dist/大麦抢票/` —— 子项都搬得动，只有目录本身动不了。
被占住的空壳目录不影响使用，等占用它的东西退出（一般重启一次就没了）再删。

**⑨ 自用的那份 `dist/大麦抢票/` 里带着账号和登录态，换代码时别整个覆盖
（2026-10-08 补）。**

`dist/大麦抢票/` 有两种身份，别搞混：**给客户的那份必须干净**，
**自己用来跑的那份里面有 `accounts.json` / `credentials.json` /
`profiles/` / `logs/`** —— 后者丢了就得重新登录、重新填账号。

所以「改了源码，想把新代码换到自己正在跑的那份里」时，**只换两样东西**：

```
大麦抢票.exe   +   _internal/
```

换法（`_newdist` 是新打出来的干净目录，见 ⑧）：

```bash
cd dist
BK="_old/$(date +%Y%m%d-%H%M%S)"; mkdir -p "$BK"
mv "大麦抢票/大麦抢票.exe" "$BK/"          # 旧的挪走，不是删
mv "大麦抢票/_internal"   "$BK/"
cp "_newdist/大麦抢票/大麦抢票.exe" "大麦抢票/"
cp -r "_newdist/大麦抢票/_internal"  "大麦抢票/"
```

`chromedriver.exe` 和两份 md 一般不用动（内容没变）。换完跑
`packaging/verify.py` —— 里面那组**哨兵**会直接从 exe 的 PYZ 里搜标记串，
源码改了没重打就会红（`h5-ultron-buy` / `viwer-info-name` /
`icondanxuan-xuanzhong_` / `立即购票` / `order_page_submit_dump.txt`）。

顺手留下的 `_newdist/大麦抢票/` 正好是**干净交付版**（没有账号和登录态），
要发客户就用它。

## 打包环境

`.build-venv/` 是**专门为打包建的**，放在项目根目录，不进交付包。
建它的原因很直接：机器上原来两个解释器都不满足条件 ——
系统 Python 3.10 有 tkinter 但没 selenium，damai 那个 venv 有 selenium 但没 tkinter。
要同时有 tkinter（界面）+ selenium（浏览器）+ PyInstaller（打包），只能新建一个。

```
python -m venv .build-venv
.build-venv/Scripts/python -m pip install selenium pyinstaller chromedriver-autoinstaller
```

装依赖时本机代理会拦国内镜像源（403），用官方源。

## 打包改了什么

exe 里 `__file__` 指向临时目录，退出就删。直接打包有两个致命问题，
所以先做了改造：

| 问题 | 原来的写法 | 改造后 |
|---|---|---|
| 数据落到临时目录 | `BASE_DIR = os.path.dirname(__file__)` | 走 `app_paths.py`：源码形态返回原值（一字不差），exe 形态返回 **exe 同级目录**，写不进去就退到 `%APPDATA%` |
| 子进程起不来 | 子进程是 `[python.exe, account_runner.py, run, id]` | exe 里没有 python 也没有 .py 文件，改成 `[大麦抢票.exe, --runner, run, id]` —— **exe 自己扮演调度器** |
| 找不到驱动 | 只找 PATH / 当前目录 / 缓存 | 增加「exe 同级 / 随包目录」，而且**先验版本再用** —— 带一份版本不对的驱动反而会挡住自动下载那条路 |

数据不落对地方的后果特别严重，而且只有第二次启动才看得出来：
**每次打开账号全空**。所以有专门的验证（见下）。

## 角色分发

同一个 exe 有两种身份，靠第一个参数区分：

```
大麦抢票.exe                  → 图形向导（控制台窗口会被藏起来）
大麦抢票.exe --runner <参数>  → 调度器子进程，参数原样转交 account_runner
大麦抢票.exe --runner --paths → 打印「程序目录 / 资源目录 / 数据目录」在哪
```

`--runner` 那一路**不能藏控制台** —— 那个窗口正是用户看登录进度、看抢票过程的地方，
藏了就等于「点了一下什么都没发生」。所以只对向导角色调 `ShowWindow(SW_HIDE)`。

`--runner --paths` 是留给客户报障用的：打包版最容易出问题的地方就是数据落错地方，
有了这条命令，客户截个图就能定位。它不依赖 selenium，**最坏情况下也能跑**；
现在它还会把随包模块逐个 import 一遍（见上面「验证过什么」）。

## 随包的 chromedriver 只是兜底

客户机器上的 Chrome 版本多半跟打包机不同，所以程序运行时还是按版本匹配、
必要时自己下载。带一份的意义是网络不通时也还有东西可用。
带之前会验版本，对不上就不带。

## 交付前核对

1. `dist/大麦抢票/` 里**没有** `accounts.json` / `credentials.json` / `accounts.log` /
   `profiles/` / `runs/`（那是每台机器自己的，`build.py` 打完会自动清）
2. `dist/大麦抢票/` 整个文件夹压成 zip 发出去，**不要**只发 exe
3. 发出前跑一遍 `packaging/verify.py`，确认全过
